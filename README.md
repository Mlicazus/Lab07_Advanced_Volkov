# ПР7. Ответы на контрольные вопросы

## Почему ChangeName изменяет объект, видимый снаружи, а ReplaceHero не заменяет исходную переменную?

Ответ: Потому что в ChangeName меняется ссылка на объект, вместо прямого изменения переменной.

## Почему следующий код (void Print) не компилируется?

Ответ: Потому что in не позволяет менять значение внутри метода.

## Почему этот метод невозможно реализовать с обычными параметрами так, чтобы изменения были видны вызывающему коду?

Ответ: Потому в метод попадает только копия переменной.

## 1. Что именно копируется при передаче параметра по значению? Объясните разницу для int и для объекта класса.

Ответ: Для int копируется число/строка, для объекта "значение" копируется ссылка на объект.

## 2. В чём разница между ref и out с точки зрения обязательной инициализации переменной до и после вызова метода?

Ответ: ref требует инициализации переменной до вызова, а out вообще этого не требует.

## 3. Почему у int.TryParse используется именно out, а не ref, для параметра, куда записывается результат?

Ответ: Потому что ему не важно что было в переменной раньше.

## 4. Какую проблему решает in? Почему он интереснее для больших структур, чем для int?

Ответ: in запрещает менять значения переменной в методах, для больших структур он нужен, чтобы не копировать все поля.

## 5. В каком порядке относительно обязательных параметров должны располагаться необязательные параметры?

Ответ: Необязательные параметры должны идти после всех обязательных в списке параметров.

## 6. В чём преимущество именованных аргументов при вызове метода с несколькими необязательными параметрами?

Ответ: Можно менять порядок и пропускать предшествующие необязательные значения.
